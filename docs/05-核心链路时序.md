> 版本:v1.0 · 状态:已定稿

## 2. 普通下单

```
客户端        OrderController     商品/库存          订单表          Kafka       通知消费者
  │               │                 │                │              │            │
  │ POST /orders  │                 │                │              │            │
  │ Idem-Key      │                 │                │              │            │
  ├──────────────>│                 │                │              │            │
  │               │ 1. 校验幂等键    │                │              │            │
  │               ├────────────────────────────────>│              │            │
  │               │                 │                │              │            │
  │               │ 2. 查商品 + 校验状态/库存        │              │            │
  │               ├────────────────>│                │              │            │
  │               │                 │                │              │            │
  │               │ 3. 开启事务      │                │              │            │

  │               ├────────────────────────────────>│              │            │
  │               │ 5. 写 Outbox(PENDING)           │              │            │
  │               ├────────────────────────────────>│              │            │
  │               │ 6. 提交事务      │                │              │            │
  │               │                 │                │              │            │
  │  <────────────┤ 201 {order}     │                │              │            │
  │               │                 │                │              │            │
  │               │ 7. 异步投递 Kafka│                │              │            │
  │               ├──────────────────────────────────────────────>│            │
  │               │                 │                │              │ 8. 推送商户 │
  │               │                 │                │              ├───────────>│
```

### 关键点

1. **扣库存用条件更新**,不是先查再改:
   ```sql
   UPDATE tb_product
   SET stock = stock - #{qty}, sold = sold + #{qty}, version = version + 1
   WHERE id = #{id} AND stock >= #{qty} AND status = 'ON_SALE' AND version = #{version};
   ```
   影响行数为 0 → 库存不足或并发冲突 → `409` + `5003`。

2. **订单与 Outbox 在同一事务**,保证"落库成功即可投递"。

3. **幂等三层**:
   - `Idempotency-Key` 唯一索引
   - `order_no` 唯一索引
   - 客户端重试拿到同一结果

4. **超时关闭**:订单创建时写入 Redisson 延迟队列,30 分钟后检查状态;仍为 `CREATED` 则关闭并回滚库存。

### 失败处理

| 阶段 | 失败 | 处理 |
|---|---|---|
| 校验 | 商品下架 / 库存不足 | 直接返回,不写库 |
| 事务 | 任一步失败 | 整体回滚 |
| 投递 | Kafka 不可用 | Outbox 保持 `PENDING`,定时任务补投 |
| 通知 | 推送失败 | 落 `tb_notification`,上线补拉 |

## 3. 优惠券秒杀

### 3.1 完整链路

```
客户端        秒杀入口             Redis              Kafka          消费者          DB
  │              │                   │                 │              │             │
  │ ① 申请令牌    │                   │                 │              │             │
  ├─────────────>│ 校验时间/资格      │                 │              │             │
  │              ├──────────────────>│ SET token TTL60s│              │             │
  │  <───────────┤ {token}           │                 │              │             │
  │              │                   │                 │              │             │
  │ ② 抢购        │                   │                 │              │             │
  ├─────────────>│ 限流(令牌桶)       │                 │              │             │
  │              ├──────────────────>│                 │              │             │
  │              │                   │                 │              │             │
  │              │ Lua 原子执行:      │                 │              │             │
  │              │  1. 令牌有效?      │                 │              │             │
  │              │  2. 库存 > 0?      │                 │              │             │
  │              │  3. 未购买过?      │                 │              │             │
  │              │  4. 扣库存         │                 │              │             │
  │              │  5. 记录用户       │                 │              │             │
  │              ├──────────────────>│                 │              │             │
  │  <───────────┤ 202 {orderNo}     │                 │              │             │
  │              │                   │                 │              │             │
  │              │ ③ 投递 Kafka       │                 │              │             │
  │              ├────────────────────────────────────>│              │             │
  │              │                   │                 │              │             │
  │              │                   │                 │ ④ 消费        │             │
  │              │                   │                 ├─────────────>│             │
  │              │                   │                 │              │ ⑤ 插入订单   │
  │              │                   │                 │              ├────────────>│
  │              │                   │                 │              │ uk_voucher_user
  │              │                   │                 │ ⑥ ACK        │             │
  │              │                   │                 │<─────────────┤             │
  │              │                   │                 │              │             │
  │              │                   │                 │ ⑦ 推送结果    │             │
  │              │                   │                 │              ├──> WebSocket
```

### 3.2 Lua 脚本要点

```lua
-- 原子完成:令牌校验 → 库存校验 → 一人一单 → 扣减 → 标记
-- KEYS[1] = 库存 key
-- KEYS[2] = 已购用户 Set
-- KEYS[3] = 令牌 key
-- ARGV[1] = userId
-- 返回:0 成功 / 1 库存不足 / 2 重复购买 / 3 令牌无效
```

三条校验与扣减必须在**同一段 Lua** 中,不能拆成多次 Redis 调用。

### 3.3 一致性保障

| 风险 | 措施 |
|---|---|
| 超卖 | Lua 原子扣减 + DB `stock >= 0` |
| 一人多单 | Redis Set + `uk_voucher_user` 唯一索引 |
| 扣减成功但落库失败 | Outbox + 重试 + 对账补偿 |
| 消息重复 | 消费端按 `order_no` / 唯一索引幂等 |
| Redis 与 DB 不一致 | 定时对账任务,差异写 `tb_reconcile_log` |
| Redis 宕机 | 活动降级为"排队中",停止新增扣减 |

### 3.4 消费失败处理

```
消费失败
   │
   ├─ 可重试(网络/DB 抖动)→ retry topic(指数退避)→ 成功则 ACK
   │
   ├─ 超过重试次数 → 死信 topic(DLQ)→ 告警 + 人工处理
   │
   └─ 业务性失败(重复订单)→ 记录并 ACK,不重试
```

**Kafka 没有原生重试队列,retry topic 与 DLQ 必须自己建。**

## 4. AI 客服

### 4.1 用户端对话

```
客户端       AiController      Agent服务         工具层              LLM(DeepSeek)
  │             │                 │                │                    │
  │ POST /ai/chat                 │                │                    │
  ├────────────>│ 鉴权,取 userId │                │                    │
  │             ├────────────────>│                │                    │
  │             │                 │ 1. 组装上下文   │                    │
  │             │                 │    (最近 N 轮)  │                    │
  │             │                 │ 2. 注入系统提示  │                    │
  │             │                 │    与 userId    │                    │
  │             │                 ├───────────────────────────────────>│
  │             │                 │                │                    │
  │             │                 │ 3. LLM 决定调用工具                 │
  │             │                 │<───────────────────────────────────┤
  │             │                 │ 4. 执行工具(服务端注入 userId)     │
  │             │                 ├───────────────>│                    │
  │             │                 │                │ 查 DB(带 userId)   │
  │             │                 │<───────────────┤                    │
  │             │                 │ 5. 工具结果回填 │                    │
  │             │                 ├───────────────────────────────────>│
  │             │                 │ 6. 生成最终回答 │                    │
  │             │                 │<───────────────────────────────────┤
  │             │                 │ 7. 落库会话 + 消息                  │
  │  <──────────┤ 200 {message}   │                │                    │
```

### 4.2 关键设计

1. **身份不经过大模型。**
   ```java
   // 正确
   tool.queryOrders(UserContext.getUserId())
   // 错误:绝不接受 LLM 传入的 userId
   tool.queryOrders(llmArgs.get("userId"))
   ```

2. **工具即权限边界。**
   - 用户端工具只有 `queryRecentProducts` / `queryMyOrders` / `queryPlatformNotices` / `queryWeather`
   - 商户端工具只有 `queryShopProducts` / `queryShopOrders` / `queryShopStats`
   - 工具内部用当前登录身份查询,天然隔离

3. **限流与降级。**

   | 场景 | 处理 |
   |---|---|
   | 单用户超过 20 次/分钟 | `429` + `1003` |
   | LLM 超时(>15s) | 降级话术 + 人工入口 |
   | LLM 不可用 | `503` + `10001`,不影响主业务 |
   | 内容不合规 | `422` + `10003` |

4. **成本控制。**
   - 上下文只带最近 10 轮
   - 工具结果做摘要,不整段塞回
   - 记录 `tokens_in` / `tokens_out`,便于统计

## 5. 实时通知

### 5.1 在线推送

```
业务服务         Kafka         通知消费者       连接注册表        WebSocket
   │               │               │               │                │
   │ 事件(Outbox)  │               │               │                │
   ├──────────────>│               │               │                │
   │               │ 消费          │               │                │
   │               ├──────────────>│               │                │
   │               │               │ 查在线连接     │                │
   │               │               ├──────────────>│                │
   │               │               │ 找到本节点连接 │                │
   │               │               │<──────────────┤                │
   │               │               │ 推送           │                │
   │               │               ├───────────────────────────────>│
   │               │               │ 落库通知        │                │
   │               │               ├──> tb_notification              │
```

### 5.2 离线与多实例

| 场景 | 处理 |
|---|---|
| 用户不在线 | 只落库,不推送 |
| 用户连在其他实例 | 通过 Redis Pub/Sub 广播到目标节点 |
| 推送失败 | 落库,客户端重连后拉取未读 |
| 客户端断线重连 | 先拉 `GET /notifications`,再建立 WS |

**多实例广播:**

```
节点 A 收到事件
   │
   ├─ 本地连接表命中 → 直接推送
   │
   └─ 未命中 → PUBLISH clp:notify:channel {userId, message}
                  │
                  └─ 所有节点订阅 → 各自查本地连接表 → 命中的节点推送
```

### 5.3 连接管理

- 握手:`/ws/notifications?token=...`,校验失败关闭
- 心跳:客户端 30s `ping`,服务端 `pong`;60s 无心跳断开
- 在线标识:`clp:notify:online:{userId}` = 节点 ID,TTL 5min 并续期
- 并发连接上限:单用户 1 个(新连接踢掉旧连接)

## 6. 失败处理总表

| 链路 | 失败点 | 兜底策略 |
|---|---|---|
| 登录 | 短信服务不可用 | 返回明确提示,不影响已登录用户 |
| 下单 | 库存并发冲突 | 条件更新失败 → 返回库存不足 |
| 下单 | Kafka 不可用 | Outbox 补投 |
| 秒杀 | Redis 宕机 | 停止入口,返回排队中 |
| 秒杀 | 消费失败 | retry topic → DLQ → 人工 |
| 秒杀 | 数据不一致 | 定时对账 + 补偿 |
| AI | LLM 超时 | 降级话术 |
| AI | 调用超限 | 429 |
| 通知 | 推送失败 | 落库 + 上线补拉 |
| 全局 | 依赖服务异常 | 熔断降级,不雪崩 |
