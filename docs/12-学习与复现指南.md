## 1. 先搞清楚:仓库里有什么,你要准备什么

仓库里已经有:

| 类别 | 必须 | 说明 |
|---|---|---|
| JDK 21 + Maven 3.9+ | ✅ | 编译和启动 |
| MySQL 8.0+ | ✅ | 业务数据;知识库用到 ngram 全文索引 |
| Redis 7 | ✅ | 缓存、限流、秒杀、会话锁 |

| DeepSeek Key | 可选 | 不填则 AI 对话降级,其他功能正常 |

## 3. 第一步:数据库

### 3.1 建库

```bash
mysql -u root -p -e "
CREATE DATABASE IF NOT EXISTS clp
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;"
```

### 3.2 建表

```bash
mysql --default-character-set=utf8mb4 -u root -p clp < sql/01-schema.sql
```

这个文件由 `docs/04-数据模型.md` 汇总而来,共 **25 张表**。

验证:

```bash
mysql -u root -p -N -e "
SELECT COUNT(*) FROM information_schema.tables WHERE table_schema='clp';"
# 期望输出 25
```

> 如果 `tb_knowledge_chunk` 的 `FULLTEXT ... WITH PARSER ngram` 报错,说明 MySQL 版本过低或未启用 ngram。  
> 代码里关键词召回有 `LIKE` 兜底,应用仍能启动,但检索效果会下降。

### 3.3 演示数据(可选,但强烈建议)

```bash
mysql --default-character-set=utf8mb4 -u root -p clp < sql/02-demo-data.sql
```

会准备:

| 数据 | 值 |
|---|---|
| 管理员账号 | `13900000000`,角色 `ADMIN` |
| 商户账号 | `13900000001`,角色 `MERCHANT` |
| 商户记录 | 已审核通过(`APPROVED`) |
| 店铺 | 「演示小店」,营业中(`OPEN`) |
| 商品 | 手工水饺 / 冰镇酸梅汤 / 招牌炒饭 |

验证:

```bash
mysql -u root -p -e "
USE clp;
SELECT id, phone, role FROM tb_user WHERE phone IN ('13900000000','13900000001');
SELECT id, name, status FROM tb_shop;
SELECT id, name, price, stock FROM tb_product;"
```

> 演示数据可以重复执行:手机号已存在时会升级角色,商户的 `user_id` 会通过手机号自动对齐真实用户,不会出现悬空引用。

### 3.4 普通用户不需要预置

任意手机号走验证码登录时会自动注册,角色默认 `USER`。

### 3.5 管理员账号怎么来

生产环境应通过安全流程初始化。本地直接用 `sql/02-demo-data.sql`,或者:

```sql
UPDATE tb_user SET role = 'ADMIN' WHERE phone = '你的手机号';
```

改完角色后需要**重新登录**,因为角色写在 JWT 里。

## 4. 第二步:Redis

### 4.1 启动

```bash
docker run -d --name redis \
  -p 6379:6379 \
  redis:7.2.14 \
  --requirepass "$REDIS_PASSWORD"
```

如果容器已存在:

```bash
docker start redis
```

验证:

```bash
docker exec redis redis-cli -a "$REDIS_PASSWORD" ping
# PONG
```

### 4.2 配置

`application-local.yml`:

```yaml
spring:
  data:
    redis:
      password: your_redis_password
```

### 4.3 Redis 里会有什么

应用会自动创建,不需要手工准备:

| 前缀 | 用途 |
|---|---|
| `clp:auth:*` | 验证码、登录失败计数、refreshToken 白名单 |
| `clp:cache:shop:*` / `clp:cache:product:*` | 多级缓存的 L2 |
| `clp:seckill:*` | 秒杀库存、令牌、一人一单 |
| `clp:like:*` / `clp:feed:*` | 点赞、Feed |
| `clp:sign:*` | 签到 Bitmap |
| `clp:ai:*` | AI 限流、会话锁、查询向量、RAG 结果 |
| `clp:notify:channel` | WebSocket 跨节点广播 |

不存在的店铺/商品会缓存 `__NULL__`,TTL 2 分钟,这是防缓存穿透的空值缓存。

### 4.4 重置

```bash
docker exec redis redis-cli -a "$REDIS_PASSWORD" FLUSHDB
```

只建议在本地开发环境做,会清掉登录态、秒杀库存、缓存和 AI 会话锁。

## 5. 第三步:Kafka

### 5.1 启动

仓库根目录的 `docker-compose.yml` 只包含 Kafka 和 Kafka UI:

```bash
docker compose up -d
```

Kafka UI:`http://localhost:8081`

### 5.2 建 topic

必须建两个 topic,各 3 个分区:

```bash
# Git Bash 需要 MSYS_NO_PATHCONV=1,否则 /opt/... 会被转成 Windows 路径
MSYS_NO_PATHCONV=1 docker exec kafka /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 \
  --create --if-not-exists --topic clp-seckill-order \
  --partitions 3 --replication-factor 1

MSYS_NO_PATHCONV=1 docker exec kafka /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 \
  --create --if-not-exists --topic clp-order-event \
  --partitions 3 --replication-factor 1
```

### 5.3 查看

```bash
MSYS_NO_PATHCONV=1 docker exec kafka /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 --list

MSYS_NO_PATHCONV=1 docker exec kafka /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 --describe --topic clp-order-event
```

### 5.4 两个 topic 分别做什么

| Topic | 生产者 | 消费者 | 用途 |
|---|---|---|---|
| `clp-seckill-order` | 秒杀 Lua 成功后经 Outbox | `clp-seckill-order` | 异步创建秒杀订单 |
| `clp-order-event` | 订单状态变更经 Outbox | `clp-order-stats` | 聚合店铺日统计 |

> 如果依赖 Kafka 自动建 topic,默认只有 1 个分区,并发消费能力会受限。  
> 应用重启后消费者 rebalance 可能滞后约 30 秒,这期间 Outbox 是 `SENT`,不是丢消息。

## 6. 第四步:AI Key(可选)

### 6.1 DeepSeek

`application-local.yml`:

```yaml
spring:
  ai:
    openai:
      api-key: sk-your-deepseek-key
```

模型已在 `application.yml` 配好:

```yaml
spring:
  ai:
    openai:
      base-url: https://api.deepseek.com
      chat:
        options:
          model: deepseek-v4-pro
```

### 6.2 智谱

```yaml
clp:
  ai:
    zhipu:
      api-key: your-id.your-secret
```

必须是完整的 `{id}.{secret}`,只填 32 位 ID 会返回 401。  
默认模型:`embedding-3`(1024 维)、`rerank-pro`。

### 6.3 没有 Key 会怎样

- 应用仍能启动;
- 知识库种子导入会跳过;
- AI 对话会走降级话术,响应 `degraded=true`;
- 订单、秒杀、内容、通知等非 AI 功能完全不受影响。

所以学习非 AI 模块时,可以先不配 Key。

## 7. 第五步:本地配置

### 7.1 复制模板

```bash
cp clp-core-service/src/main/resources/application-local.yml.example \
   clp-core-service/src/main/resources/application-local.yml
```

`application-local.yml` 已被 `.gitignore` 忽略,不会提交。

### 7.2 必填项

```yaml
spring:
  datasource:
    password: your_mysql_password
  data:
    redis:
      password: your_redis_password
  ai:
    openai:
      api-key: sk-your-deepseek-key

clp:
  jwt:
    secret: your-32-byte-minimum-secret
  ai:
    zhipu:
      api-key: your-id.your-secret
```

### 7.3 几个关键配置

| 配置 | 默认值 | 说明 |
|---|---|---|
| `spring.profiles.active` | `local` | 已写在 `application.yml` |
| `server.port` | `8080` | 启动时可覆盖 |
| `clp.jwt.secret` | 空 | 少于 32 字节应用启动失败 |
| `clp.order.timeout` | `30m` | 未支付关单时间 |
| `clp.feed.big-v-threshold` | `1000` | 大 V 阈值 |
| `clp.cache.*` | 见配置 | 两级缓存 TTL、空值缓存 |
| `clp.ai.chat.timeout-ms` | `15000` | 模型调用硬超时 |
| `clp.ai.rag.*` | 见配置 | 召回数量、RRF、精排、阈值 |

1. 用 `13900000000` 登录;
2. 打开 `/admin/dashboard.html`;

1. 任意手机号登录(自动注册);
2. 浏览店铺和商品;
3. 下单(必须带 `Idempotency-Key`);
4. 支付;
5. 等商户接单/完成;

## 11. 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动报 `clp.jwt.secret 至少需要 32 字节` | secret 太短 | 换 32 字节以上 |
| 智谱返回 401 | Key 只填了 32 位 ID | 填完整 `{id}.{secret}` |
| AI 一直降级 | Key 未配置 / 网络不通 / 熔断 | 看日志和 `degraded` 字段 |
| 知识库没导入 | 没配智谱 Key | 配 Key 后重启,或走管理端导入接口 |
| Kafka 消费者没数据 | topic 没建 / 分区不对 | 手工建 3 分区 topic |
| `docker exec` 找不到 `/opt/kafka/...` | Git Bash 路径转换 | 命令前加 `MSYS_NO_PATHCONV=1` |
| 端口被占用 | 旧进程未退出 | `--server.port=8084` 或结束旧进程 |
| 改了角色但没权限 | 角色写在 JWT | 重新登录 |
| 店铺/商品详情读到旧值 | 多级缓存 L1 最多 60 秒 | 等 TTL,或手动删 Redis key |
| 不存在的 ID 一直查库 | 空值缓存只有 2 分钟 | 正常现象,2 分钟后重新回源 |
| 日统计没有历史数据 | 统计从功能上线开始累积 | 没有回填任务,属于已知边界 |
| MySQL 全文索引报错 | 版本低于 8 或没有 ngram | 用 MySQL 8.0+ |
| 时间差 8 小时 | 时区不是 Asia/Shanghai | 检查 JDBC `serverTimezone` 和 JVM 时区 |

## 13. 学习路线

建议按这个顺序读代码和文档:

1. **README** → 知道项目有什么。
2. **docs/01 业务定义** → 角色、业务域、状态机。
3. **docs/02 接口规范** → 统一响应、错误码、鉴权、幂等。
4. **登录链路**:`AuthController` → `AuthServiceImpl` → `JwtTokenProvider` → `JwtAuthInterceptor`。
5. **下单链路**:`OrderController` → `OrderServiceImpl` → `OrderTxService` → `OutboxService` → Kafka。
6. **秒杀链路**:`docs/09` + `SeckillServiceImpl` + `lua/seckill.lua`。
7. **AI 链路**:`docs/10` + `AiChatController` → `AiChatServiceImpl` → `SpringAiChatGateway` → 工具/RAG。
8. **数据链路**:`docs/11` + `OrderEventPublisher` → `OrderEventConsumer` → `StatsQueryService`。
9. **测试**:`src/test` 里每个测试都是行为说明,先读测试再读实现。
10. **改一个小功能**:加一个接口 → 加测试 → 跑冒烟,形成闭环。
11. **管理端前端**(可选):读 `clp-admin-web/README.md`,重点看 `src/api/http.ts`(axios 拦截器)和 `src/views/*.vue`(SFC + Composition API)。
