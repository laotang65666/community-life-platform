# 02 · 接口规范

> 版本:v1.0 · 状态:已定稿
> 所有接口必须遵守本规范。新增接口先改本文件,再写代码。

---

## 1. 总则

| 项 | 规定 |
|---|---|
| 风格 | RESTful,资源导向 |
| 协议 | HTTP/1.1(WebSocket 单独约定) |
| 编码 | UTF-8 |
| 数据格式 | `application/json` |
| 版本 | URL 路径版本化:`/api/v1` |
| 字段命名 | JSON 使用 `camelCase` |
| 资源命名 | 复数名词 + `kebab-case` |

---

## 2. URL 规范

### 2.1 基本格式

```
/api/v1/{resource}
/api/v1/{resource}/{id}
/api/v1/{resource}/{id}/{sub-resource}
```

### 2.2 规则

1. **只用名词,不用动词。**
   - ✅ `POST /api/v1/orders`
   - ❌ `POST /api/v1/createOrder`
2. **资源用复数。**
   - ✅ `/api/v1/users`
   - ❌ `/api/v1/user`
3. **多单词用 kebab-case。**
   - ✅ `/api/v1/blog-posts`
   - ❌ `/api/v1/blogPosts`
4. **嵌套最多两级。** 更深的用查询参数。
   - ✅ `/api/v1/shops/{shopId}/products`
   - ❌ `/api/v1/shops/{shopId}/products/{productId}/comments/{commentId}`
5. **非 CRUD 动作用子资源 + POST。**
   - ✅ `POST /api/v1/orders/{orderId}/cancel`
   - ❌ `POST /api/v1/orders/cancel?id=`
6. **当前用户用 `me`,不用传 userId。**
   - ✅ `GET /api/v1/users/me`
   - ❌ `GET /api/v1/users/current?id=123`
7. **路径参数只能是 ID,复杂筛选走 query。**

### 2.3 HTTP 方法语义

| 方法 | 语义 | 幂等 | 安全 |
|---|---|---|---|
| GET | 查询 | ✅ | ✅ |
| POST | 创建 / 非幂等动作 | ❌ | ❌ |
| PUT | 全量更新 | ✅ | ❌ |
| PATCH | 部分更新 | ✅ | ❌ |
| DELETE | 删除 | ✅ | ❌ |

> 项目首期统一用 `POST` 创建、`PATCH` 局部更新、`DELETE` 删除。`PUT` 全量替换暂不使用。

## 3. 请求规范

### 3.1 通用请求头

| Header | 必填 | 说明 |
|---|---|---|
| `Authorization` | 登录接口外必填 | `Bearer <accessToken>` |
| `Content-Type` | 有请求体时必填 | `application/json` |
| `Idempotency-Key` | 下单 / 秒杀必填 | 客户端生成的 UUID,24 小时内唯一 |
| `X-Request-Id` | 可选 | 客户端追踪 ID,服务端回传 |
| `Accept-Language` | 可选 | `zh-CN` / `en-US` |

### 3.2 路径参数

- 一律为字符串形式的 ID(雪花 ID 超过 JS 安全整数,必须用字符串)。

### 3.3 查询参数

| 参数 | 说明 | 默认 |
|---|---|---|
| `page` | 页码,从 1 开始 | 1 |
| `size` | 每页条数,最大 100 | 10 |
| `sort` | 排序,格式 `字段,asc\|desc` | 各接口定义 |
| 其他 | 各接口定义 | — |

### 3.4 请求体

- 字段使用 `camelCase`。
- 必填字段缺失或格式错误 → `400` + `1001`。
- 服务端不做"缺省即空"的隐式处理。

## 4. 响应规范

### 4.1 统一响应体

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "traceId": "7f3c9a2e"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | `0` 表示成功;非 0 为业务错误码 |
| `message` | string | 人类可读信息;错误时为错误描述 |
| `data` | any | 业务数据;无数据时为 `null` |
| `traceId` | string | 链路追踪 ID,排查问题用 |

### 4.2 成功响应

创建类返回 `201`,并携带资源:

```json
{
  "code": 0,
  "message": "ok",
  "data": { "id": "1843920128374123008" },
  "traceId": "7f3c9a2e"
}
```

删除类返回 `204`,无响应体。

### 4.3 分页响应

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [],
    "page": 1,
    "size": 10,
    "total": 128,
    "pages": 13
  },
  "traceId": "7f3c9a2e"
}
```

### 4.4 错误响应

```json
{
  "code": 7002,
  "message": "秒杀已结束",
  "data": null,
  "traceId": "7f3c9a2e"
}
```

### 4.5 HTTP 状态码

| 状态码 | 使用场景 |
|---|---|
| `200` | 查询 / 更新成功 |
| `201` | 创建成功 |
| `204` | 删除成功,无响应体 |
| `400` | 参数错误 |
| `401` | 未登录 / token 无效或过期 |
| `403` | 已登录但无权限 |
| `404` | 资源不存在 |
| `409` | 状态冲突(如重复下单、库存不足) |
| `422` | 业务校验失败 |
| `429` | 触发限流 |
| `500` | 服务端异常 |
| `503` | 依赖服务不可用(AI / MQ) |

> **约定:业务错误同时体现在 HTTP 状态码和 `code`。** 例如库存不足 = `409` + `5003`。

## 5. 认证与鉴权

### 5.1 登录流程

```
POST /api/v1/auth/sms-code     发送验证码
POST /api/v1/auth/login        手机号 + 验证码 → accessToken + refreshToken
POST /api/v1/auth/refresh      用 refreshToken 换新 token
POST /api/v1/auth/logout       吊销 refreshToken
```

### 5.2 Token 规范

| Token | 有效期 | 存放 |
|---|---|---|
| `accessToken` | 30 分钟 | 客户端内存 / 安全存储 |
| `refreshToken` | 7 天 | 客户端安全存储 |

响应:

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "accessToken": "eyJ...",
    "refreshToken": "eyJ...",
    "expiresIn": 1800,
    "role": "USER"
  }
}
```

### 5.3 鉴权规则

- 拦截器解析 token,失败直接 `401`。
- 角色校验注解:`@RequireRole(MERCHANT)`、`@RequireRole(ADMIN)`。
- `MERCHANT` 通过校验时视为拥有 `USER` 权限。
- **数据归属校验必须在 Service 层做**,不能只靠 URL 参数。

## 6. 幂等规范

### 6.1 需要幂等的接口

| 接口 | 机制 |
|---|---|
| `POST /api/v1/orders` | `Idempotency-Key` + 订单号唯一索引 |
| `POST /api/v1/vouchers/{id}/orders` | `Idempotency-Key` + `(voucher_id, user_id)` 唯一索引 |
| `POST /api/v1/sign-ins` | `(user_id, date)` 唯一约束 + Redis 标记 |

### 6.2 行为

- 相同 `Idempotency-Key` 24 小时内返回首次结果,不重复执行。
- 未携带 `Idempotency-Key` 的下单请求 → `400` + `1001`。

## 8. 数据类型约定

### 8.1 ID

- 雪花 ID 为 64 位整数,**JSON 中一律序列化为字符串**。
- 示例:`"id": "1843920128374123008"`

### 8.2 金额

- 类型:`Long`,单位:**分**。
- 字段命名:`amount` / `price` / `totalAmount`。
- 示例:`"price": 1990` 表示 19.90 元。
- **禁止**使用 `double` / `float`。

### 8.3 时间

- 格式:ISO 8601 带时区。
- 示例:`"createdAt": "2026-10-17T12:00:00+08:00"`
- 日期字段:`"date": "2026-10-17"`

### 8.4 布尔

- `true` / `false`,禁止 `0` / `1`。

### 8.5 枚举

- 统一大写 + 下划线:`USER`、`ON_SALE`、`CREATED`。
- 响应中返回枚举字符串,同时可在文档中列出全部取值。

## 9. 限流规范

### 9.1 触发限流

返回 `429`:

```json
{
  "code": 1003,
  "message": "请求过于频繁,请稍后重试",
  "data": null,
  "traceId": "7f3c9a2e"
}
```

响应头:

```
X-RateLimit-Limit: 20
X-RateLimit-Remaining: 0
Retry-After: 30
```

### 9.2 限流维度

| 场景 | 维度 | 建议阈值 |
|---|---|---|
| 普通接口 | 用户 | 60 次 / 分钟 |
| 登录 / 验证码 | IP + 手机号 | 5 次 / 分钟 |
| 秒杀入口 | 全局 + 用户 | 全局 QPS + 1 次 / 秒 |
| AI 客服 | 用户 | 20 次 / 分钟 |

## 10. WebSocket 规范

### 10.1 连接

```
ws://{host}/ws/notifications?token={accessToken}
```

- 握手时校验 token,失败关闭连接(code `4001`)。
- 客户端每 30 秒发送心跳 `{"type":"ping"}`,服务端回 `{"type":"pong"}`。

### 10.2 消息格式

```json
{
  "type": "ORDER_CREATED",
  "data": {
    "notificationId": "1843920128374123008",
    "title": "新订单",
    "content": "您有一笔新订单待处理",
    "bizId": "1843920128374123999",
    "createdAt": "2026-10-17T12:00:00+08:00"
  }
}
```

### 10.3 消息类型

| type | 接收方 | 说明 |
|---|---|---|
| `ORDER_CREATED` | 商户 | 用户下单 |
| `ORDER_ACCEPTED` | 用户 | 商户接单 |
| `ORDER_COMPLETED` | 用户 | 订单完成 |
| `SECKILL_RESULT` | 用户 | 秒杀结果 |
| `MERCHANT_AUDIT` | 用户 | 商户审核结果 |
| `SYSTEM_NOTICE` | 全部 | 系统公告 |

### 10.4 离线补偿

- 推送失败或用户离线 → 落库 `tb_notification`。
- 客户端重连后调用 `GET /api/v1/notifications` 拉取未读。
